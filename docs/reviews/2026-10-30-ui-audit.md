# UI audit, 30 October 2026

This audit covers the whole web UI (`apps/ui`):
- the shell, Dashboard, Explorer and records, Species, Settings, Add observation, Model evaluation,
  Audio history, Notifications, About, Login and the first-run wizard;
- light and dark themes, owner and public visitor views;
- widths from 320 to 1440 px, and 200% text at 320 px.

It followed `docs/standards/ui-ux.md`, `layout-patterns.md`, `diagnostics-and-dialogs.md` and
CLAUDE.md §4–6. The audited checkout was `dev` plus #826 (Garden for visitors) and #827 (filter
rail).

**Method.** Four reviewers worked in parallel, one per area, with performance and kit consistency as
the fourth. Each finding is backed by at least one of the following:
- a screenshot from the Playwright fixtures;
- a code path read end to end;
- a measurement against the production build;
- a measurement of the live instance read as a guest, using GET requests only.

Screenshots and raw measurements were kept outside the repository, on the review host, in
`/mnt/apps/developer/jellman86/tmp/ui-audit-20261030/`.

## 1. Summary

**What is solid.**
- The core layouts follow their standards. The Dashboard reads as one window of visits, the
  Explorer interleaves birds and Garden animals honestly, and Settings tabs mostly use the
  primitives kit.
- Every connection test goes through the shared diagnostic dialog.
- No surface overflows sideways at normal text size, at any width or in either theme.
- Filter changes return in 200–350 ms with no long tasks.

**What is weak.** Most defects sit in the states around the main path, and in drift between
sibling components.

Wrong or unmeasured states:
- A failed Explorer load says "No events yet".
- A first load says "0 visits".
- About says the classifier is "not loaded" while it is classifying.
- A guest is told notifications are off.
- A guest reads "Identified by you".

Colour rules contradict the standard:
- The same score is three colours across Cards, List and the record.
- "Needs a person" uses the theme accent, which is emerald in one theme and amber in another.
- Success and warning toasts are identical in the shipped theme.

Data safety:
- Shortening history retention schedules permanent deletion with no warning or count.
- Settings loses unsaved edits on navigation.
- An uploaded photo is stamped with the time you pressed Save, not when it was taken.

Accessibility blockers:
- The closed mobile menu keeps 12 invisible tab stops ahead of the page.
- The camera buttons in Settings are all named "Select".
- Pages overflow at 320 px with 200% text.
- Several dialogs (the bulk species picker, the video player) do not trap focus.

Speed is mostly request hygiene, not rendering:
- **First visit:** a guest's cold Dashboard load is 2.29 MB over 93 requests. That includes the
  214 kB classifier label list twice, which a guest cannot use.
- **Idle tabs:** an idle tab pulls about 19 MB an hour.
- **Unused code:** the record modals load for every visitor before anything is opened.
- **Compression:** API JSON is sent uncompressed.
- **Layout shift:** CLS is poor on phones (Dashboard 0.79 throttled).

### Biggest wins

1. **One colour language for state:**
   - one `scoreTone()` helper;
   - a fixed `attention-*` amber token;
   - `success-*` for confirmation;
   - AA-safe brand fills.

   This is a mechanical change that restores the amber rule in every theme.
2. **Honest states.** The Explorer error, first-load and refetch states, the classifier pipeline
   state, guest wording, toasts that wait, and an unknown-page screen.
3. **Request hygiene:**
   - classifier labels only for owners and only when needed;
   - no double first read;
   - modals loaded on first open;
   - gzip for JSON;
   - telemetry polling scaled for guests.

## 2. Findings

- **Blocker:** wrong state shown, inaccessible, or broken.

Effort: S is under half a day, M is one to two days, L is longer. The last column names the slice
in §5 that fixes it.

## 3. Cross-cutting opportunities

- **SegmentedControl, `.choice-chip` and `.choice-row`.** One look for a chosen option, with radio or
  pressed semantics.
  - Call sites: ExplorerFilters, Events (Cards/List), `SettingsSegmented` (7 uses),
    FamilyTreeDialog, Species, ManualObservation, CaptureWall, Notifications, GardenBetaSettings,
    GardenNotificationSettings, ConnectionSettings and SpeciesCheckSheet.
- **Score tone, state tone and an `attention-*` token.** One `utils/tone.ts` built on `attention-*`
  (fixed amber), `success-*`, `brand-*` and `rose-*`.
  - Score call sites: DetectionCard, DetectionRow, DetectionModal, GardenExplorerCard,
    GardenExplorerRow, GardenCaptureModal, VisitCaptures, HealthActivityTimeline, ReviewQueueModal
    and AudioHistory.
  - State call sites: DayBar, ReviewQueueCard, FieldLogVisitRow, Notifications, Errors, Toast and
    ConnectionStatus.
- **Dialog shell and SpeciesPickerDialog.** trapFocus, Escape and focus return.
  - The bulk picker and VideoPlayer lack them.
  - The record picker and the counted-bird editors duplicate the species search.
- **StatusBand and InlineNotice.** Nine notice variants in Events, plus Settings, ManualObservation,
  ModelEvaluation, AudioHistory, Login and the wizard. Each needs its tone and role.
- **EmptyState and skeleton.** Empty states in FieldLog, Events, AudioHistory, NotableNearby,
  ConnectionSettings, HeardBandCard and InstancePipeline. A `.skeleton` class to replace about
  30 hand-copied pulse strings.
- **Kit gaps.** `.btn` and `.tab-button` have no minimum height. The `.select-base` chevron is
  invisible in dark mode. `.btn-icon` is used once.
- **`lazyComponent()` and `cachedGet()`.** Generalise the route loader for the modals, Settings tabs
  and wizard. Share one cached GET for labels, species info and audio summary.
- **Locale safety.** A test that every `$_()` default's placeholders exist in the locale value
  (SET-04). A rule that `{count} noun` strings are ICU plurals (DB-06).

## 5. Sequenced plan

Each slice is one branch and one PR. Slices 1–5 touch separate areas and can run in parallel. The
rest follow in order.

1. **Shell honesty and accessibility:** AB-01, SH-01, SH-02, SH-03, SH-04, SH-05, NT-01, NT-03,
   WZ-01. Risk: low; shell markup only.
2. **Explorer states:** EXP-01, EXP-03, EXP-04, EXP-06, EXP-08, EXP-11, REC-01. Risk: low; the
   Events state switch is the largest change.
3. **One colour language:** EXP-02, DB-02, NT-02, NT-04, KIT-02, AUD-03. Risk: visual change in
   every theme; it touches many components but only class names.
4. **Request hygiene:** DB-03 / PERF-01, DB-04, PERF-02, PERF-04, PERF-06, PERF-07 / SH-06,
   PERF-11. Risk: the nginx compression must exclude SSE and video; lazy modals need loading and
   error states.
5. **Settings safety and accessibility:** SET-04, SET-01, SET-06, SET-07, SET-08, SET-09, SET-11,
   SET-12, SET-14, DLG-03, AUD-01, AUD-02. Risk: a new read-only count parameter on the maintenance
   stats endpoint.
6. **Copy, plurals and small polish:** DB-06, DB-07, DB-08, DB-10, NT-05, WZ-02, WZ-03, WZ-04,
   AB-03, AB-04, SPC-01, SPC-02, EXP-10, REC-05.
7. **Layout stability:** DB-01, DB-05, AB-02, PERF-03.
8. **Rail follow-ups:** FLT-02, FLT-05, FLT-06, REC-03.
9. **Camera roles in one place:** SET-05 (the owner's per-camera "Birds / Garden animals / Both"),

## 6. Not recommended

- **Auto-saving each setting.** Several settings restart workers or change model execution, so a
  deliberate Apply is right. Fix its feedback instead (SET-02, SET-03).
- **A second Garden camera list in Connection.** That recreates the split; one row with a role
  choice is the fix (SET-05).
- **A typed "DELETE" confirmation for every destructive action.** `confirmAction` with effect-named
  labels is enough.
- **Replacing markdown-it, Chart.js or hls.js.** They are already lazy or can be deferred. Size is
  a loading problem, not a library problem.
- **Re-checking filter-change speed or hidden-tab guest polling.** Both were measured and are fine.
