A small release for anyone on 2.19.4 or 2.19.3 who keeps being told to refresh, and for
background work that says what it is doing instead of something it is not.

## Smoother everyday use

- **The "YA-WAMF was updated while this tab was open" message is gone.** On every stable image it
  appeared on every load, hard refresh included, because the interface and the backend disagreed
  about what a stable build is called and the check that spots a genuinely stale tab read the two
  names as two deployments. Your tab was always running the right build; the message was wrong.
  Both halves now use one name, and the check ignores a channel label when the build itself
  matches, so a browser that already has 2.19.4 loaded stops warning as soon as it reaches this
  backend.
- **A background job that stops reporting now says so, and leaves.** A job that went quiet used
  to be rewritten into a read update marked "stale", keeping a live-looking progress bar and an
  Open button for as long as your browser kept history, filed under Updates rather than Jobs. It
  is now shown as **stopped**, with how far it got and when it went quiet, a grey bar that no
  longer moves, its own **Dismiss**, and it leaves the history a day later. Old entries are read
  the same way, so one from last week disappears on the next load.
- **A backfill is one job, not two.** The row you watched over the live stream and the row the
  server remembered were named differently, so the top bar counted a running backfill twice and
  the history kept a row titled just "Weather" whose message was the word "completed". It is one
  row now, and once it is over the line says what it did, such as "Updated 94 detection(s)".
- **The top progress bar tells the truth about quiet work.** Its headline counts only jobs still
  reporting and says "not responding" when that is all there is. Its button read "Open Jobs"
  although the Jobs page was folded into Notifications in 2.19.3; it now says "See all work".

## Before you update

- **No special steps.** No schema changes and no settings to revisit. Unsuffixed image tags remain
  the full compatibility image; see [hardware acceleration](../setup/hardware-acceleration.md) if
  you use a provider-specific flavour.

## Good to know

- **Work in flight is drawn in the brand colour.** Amber is kept for the things that need you: a
  paused lane, a job that stopped, a detection that wants a decision. A job simply running no
  longer borrows it.
