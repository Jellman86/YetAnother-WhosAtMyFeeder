A small release for anyone who pulled `latest` and was told, or worked out for themselves, that
they were running the dev branch. You were not, but the build could not prove it.

## Smoother everyday use

- **A release image now says it is a release.** Each release is built three times within a few
  minutes: once for the `main` branch, once for the version tag, and once more when `dev` is
  brought level. All three builds pushed the same working image tag, and the release picked up
  whichever had finished last. So `latest` for 2.19.4 called itself a `dev` build and checked for
  updates against the dev branch, and 2.19.5 called itself `main`. From this release each build
  is promoted from its own image, so a release install reports a plain version such as
  `v2.19.6+abc1234` with no branch label, and looks for updates on the stable channel only.
- **The version in the footer opens the changelog for the build you are running.** It used to
  open the dev branch's changelog for every install, which read as "this is the dev branch" even
  on a release. It now opens the `main` changelog on a release and the branch's own changelog on
  a dev build, the same rule the About page already follows.

## Before you update

- **No special steps.** No schema changes and no settings to revisit. Pull `latest` or the flavour
  you use as usual. Unsuffixed image tags remain the full compatibility image; see
  [hardware acceleration](../setup/hardware-acceleration.md) if you use a provider-specific
  flavour.

## Good to know

- **If your About page shows `dev` on a 2.19.4 install, that is the label, not the code.** The
  image was built from the release commit; only its channel label was wrong. Updating to this
  release replaces both.
