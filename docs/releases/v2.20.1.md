YA-WAMF 2.20.1 makes Intel NPU video analysis substantially lighter on the host, gives you a
clear history of CPU and accelerator use, and fixes two small gaps in the visit record and signed-in
playback.

## What's new

- **See what the host has been doing.** **Settings → Health** now keeps the last thirty minutes
  of CPU and accelerator load beside the live readings. It separates YA-WAMF's own processes from
  the rest of the host without naming unrelated processes.
- **Matching calls are visible in the field log.** A visit confirmed by BirdNET-Go now says
  **matching call** beneath its name, using the same wording as the full record.

## Smoother everyday use

- **Intel NPU video analysis spends much less time on CPU work.** Frames are decoded in one
  forward pass, crop detection runs at most once per frame, and OpenVINO preprocessing is no longer
  repeated. On the reference Intel NPU host, the same retained clip fell from about 67 seconds to
  12.7 seconds and its peak container CPU use fell from about 12.7 cores to 2.4 cores. The bird
  classifier and accurate crop detector both remained on the NPU; other hardware, clips and models
  will vary.
- **Signed-in video playback keeps the owner request budget (#451).** Browser range requests and
  clip probes now recognise the scoped owner media cookie on read-only media routes, so ordinary
  playback no longer falls into the much smaller public rate limit. The cookie gains no authority
  outside those routes.

## Before you update

- **No special steps.** This release has no database migration, removed setting or changed
  default. Update the image normally and wait for the health check to pass.
- Unsuffixed image tags remain the full compatibility image; see
  [hardware acceleration](../setup/hardware-acceleration.md) if you use a provider-specific
  flavour.

## Good to know

- **Per-run video diagnostics are now retained.** Completed and abstained analyses record their
  decode, frame preparation, crop generation and bird-inference timings together with the active
  classifier and crop-detector providers. This adds diagnostics only; it does not change the
  detection database schema or identification thresholds.
