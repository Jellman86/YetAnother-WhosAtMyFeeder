A patch release for two rough edges in 2.19.0, both in features that release introduced. If you
configured Home Assistant weather in 2.19.0, please read the first item: you will need to enter
your access token once more.

## Smoother everyday use

- **Home Assistant weather settings now survive a restart.** In 2.19.0 the saved configuration was
  read from disk and then ignored, so the settings card came back blank after the next restart —
  and the following save wrote empty values over what you had entered, taking the URL, entity, and
  long-lived access token with it. The settings load correctly now.
- **The review queue shows the right time.** The *Needs your call* entries sent a timestamp with no
  timezone, which a browser reads as its own local time, so anyone outside UTC saw the sighting's
  clock shifted by their offset. Those times are explicit UTC now, like every other time in the app.

## Before you update

- **If you use Home Assistant weather, re-enter your access token after updating.** The token is
  stored write-only and cannot be recovered, so if 2.19.0 erased it, YA-WAMF cannot put it back.
  Open *Settings → Integrations → Home Assistant weather*, check the URL and entity are still what
  you expect, paste a token, and use *Fetch a live reading* to confirm before saving. Everything
  else updates with no special steps.

## Good to know

- Both faults were reported by people running 2.19.0 within a day of it shipping, and both are now
  covered by tests: one asserting a stored Home Assistant section survives a load, one asserting
  the queue's timestamps carry their timezone.
