# YA-WAMF 2.18.1

YA-WAMF 2.18.1 fixes the slowdowns at their root: bird identification now runs in its own worker
processes, memory stays flat over days instead of creeping up, and only one copy of the model is
held unless you ask for more. The Notifications and Detection settings pages were rebuilt around
that work, so what the interface says and what the runtime does are finally the same thing.

## What's new

- **Your notification policy reads as one sentence.** *Tell me about **new visits** that are at
  least **70% sure** of **any species** on **Discord and Email*** — and every highlighted word is
  the control. Destinations are named in the sentence and you can pick several at once, with an
  honest *needs setup* tag on a channel that is switched on before it is configured.
- **The Detection tab leads with its status.** A permanent band shows the active model, the
  runtime it runs on, how many workers are holding model copies, and whether anything needs your
  attention — healthy is four calm facts, and the full report opens itself only when something is
  wrong.
- **Models are chosen from cards, with memory drawn instead of recited.** Each model card carries
  one state chip and its real costs — download size and a RAM meter — and the selected model shows
  **Predicted RAM use** as honest arithmetic: model size × process mode × your worker count.
- **Worker concurrency is a setting you can actually set.** **Settings > Detection > Runtime** now
  has a **Worker processes** row. Leave it empty for the default of one worker of each kind; each
  extra worker holds its own copy of the model in memory.
- **The "open in Frigate" link can reach your browser's Frigate.** If YA-WAMF talks to Frigate at
  a container address, set **Settings > Connection > Public Frigate URL** and detection links open
  in the Frigate you can actually browse to.

## Smoother everyday use

- **The interface stays responsive while birds are identified.** Identification now runs in
  isolated worker processes by default, so a heavy classification or a stalled model no longer
  competes with the pages you are looking at, and a crashed worker is restarted without taking
  the interface down.
- **Memory stays flat.** Three leaks that made the backend grow over days are fixed — expired
  work is cleaned up promptly, the audio buffer is strictly bounded, and the OpenVINO runtime no
  longer accumulates inference state. A live installation now holds steady where it previously
  climbed.
- **One model copy by default.** A fresh install spawns one live and one background worker —
  never more unless you configure it — so the default memory footprint is one model copy per
  kind, stated plainly in the settings.
- **One concurrency control, not two.** The separate Video Concurrency setting is retired: the
  models classify one image per worker, so video analysis now simply runs as many clips at a time
  as you have background workers. The old setting is ignored harmlessly if your tools still send
  it.

## Before you update

- **No special steps.** Existing settings are respected: if your configuration already names a
  worker count, it is kept exactly as written; only installs that never set one follow the new
  one-worker default. Unsuffixed image tags remain the full compatibility image — see the
  [hardware acceleration guide](../setup/hardware-acceleration.md) if you use a provider-specific
  flavor.

## Good to know

- **The retired Video Concurrency setting no longer appears in Settings.** Its job limit now
  follows your background worker count. If you had tuned it below your worker count to hold
  workers back for other jobs, set the worker count itself instead.
- **Settings pages animate gently.** The new status band and selected model card carry a soft
  moving background; it stays on the GPU and goes completely still if your system asks for
  reduced motion.
